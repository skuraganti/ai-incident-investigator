# Investigate a local failure

1. Start the stack and capture SQLite contention. The app makes three requests with injection disabled, then three with the fault enabled. Inspect the measured statuses and the `cache.read` span; a control request can fail too, so read the recorded evidence before interpreting the label.
2. Run the deterministic baseline and open its citations. Compare the hypothesis with the exact log and trace text. Quote validation confirms the source text; it does not establish a cause. [The failure and uncertainty walkthrough](docs/FAILURE_RECOVERY.md) works without fresh model inference. An optional approved-model investigation requires the configured bridge and available budget.
3. Inspect the proposed change target, risks and verification steps. It remains **requires human approval / nonexecutable**. Export the case locally for review. There is no apply control.
4. Compare a schema-accessor failure, the sandbox’s real loopback HTTP `ReadTimeout`, and an intentionally delayed aggregation. The faults are controlled experiments. Statuses and durations are local measurements, including timing noise.
5. Inspect the healthy control and unsupported CPU-temperature question. The deterministic baseline abstains and proposes no repair when evidence is insufficient. The recorded model study did not demonstrate successful abstention: its unsupported condition never reached inference and its healthy output was rejected. Keep the synthetic injected-log probe separate from observed telemetry.
6. Filter the evidence, follow a citation with the keyboard, and inspect raw telemetry and stored failures. Switch from a complete case to a failed capture: its panel should show no evidence loaded, rather than facts from the previous case. Restart both app services and verify that saved cases, analyses and counters remain. Stop the stack when finished.

The frozen model study and its separate browser attempt stay unchanged. A later example is not a replacement for an unsuccessful condition. Current local runs can contain different timing and mixed signals; they should be recorded separately.
