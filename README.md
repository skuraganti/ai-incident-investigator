# Faultline — ai incident investigator

**[Open the GitHub Pages browser demo](https://skuraganti.github.io/ai-incident-investigator/)** · [Architecture](ARCHITECTURE.md) · [Data sources](DATA_SOURCES.md) · [Verification](VERIFICATION.md)

Faultline investigates sandboxed failures using measured logs, metrics and spans. It produces cautious hypotheses with exact evidence citations and repair proposals for human review.

## Two ways to explore

The **Pages site** shows recorded local HTTP/log/span observations from the sandbox over frozen USGS data. Fault causes are explicitly injected, and repairs are nonexecutable proposals requiring human approval. It runs in the browser with relative assets and no backend, credentials or model calls. The repository also contains the **full Python/Docker application**; Pages cannot execute its backend or background workers.

## Run the full application locally

Requirements: Python3.13+, [uv](https://docs.astral.sh/uv/), Docker and Docker Compose. No GPU is required. Run one portfolio stack at a time on a small machine.

```sh
uv sync --frozen
uv run python scripts/bootstrap.py
sh stack.sh up
```

Open **http://127.0.0.1:8286**. To stop the app, use `sh stack.sh stop`; this keeps the repository's own named volume. The helpers use the current Docker context or an explicit `DOCKER_HOST`, without choosing a personal machine profile. Images, networks and volumes use unique `portfolio-release-*` names, separate from the original development stacks. Host ports bind to 127.0.0.1.

Model integration is **optional through a locally configured host bridge**. Inference may run remotely through the already approved connection. The application starts without a model daemon. A host already configured for the approved `claude-omni` / `cookllm` connection can explicitly start `sh stack.sh bridge`. This repository contains no credentials, included model service or new-provider fallback. The Pages site never contacts that bridge. Recorded evaluations are historical observations and are not regenerated by bootstrap or tests.

## Scope and limitations

Fault causes are deliberately injected; observed errors, HTTP results and durations are actual local measurements. The frozen model study validated 2/7 conditions; two were stopped or timed out, two returned malformed JSON, and one failed before inference. A separate browser generation was also rejected. The injection answer had weak alternatives despite valid quotes. No production-RCA or repair-efficacy claim is made, and there is no repair executor.

## Implementation history

- Sandbox application failures with measured HTTP, log, metric and span evidence.
- Cited hypotheses, uncertainty and human-review repair proposals without an executor.
- A recorded-case browser investigation view, with unsuccessful model-study conditions retained in the evaluation record.

## Reading failures and uncertainty

[Recorded failures and recovery](docs/FAILURE_RECOVERY.md) explains the seven study conditions, why malformed output is kept as a failure, and how later work can continue without retrying inference. The SQLite example follows the evidence through logs and traces, including what it cannot tell us about the lock holder.

The UI selection regression can be run separately with Node (no extra packages):

```sh
node --test tests/ui-selection.test.cjs
```

It checks that moving to a failed case clears the previous case’s facts, and that delayed responses cannot replace the current selection. The Python application does not require Node.
